## 1. 一覧表(`samples/sound.html`)
- 開き方:`python3 tools/serve.py 8001`(プロジェクト直下)→ http://127.0.0.1:8001/samples/sound.html 。`python3 -m http.server` では自動保存が効かない(POST の受け口が無い。その場合は右上が赤く「保存に失敗」になり、localStorage にだけ残る)。
- **1 画面に全 69 場面を縦に並べた表**。グループ見出し(目覚め・410 と 4F/冒頭の見せ場・EV/管理人/…の 11 章)ごとに区切る。
  - 1 行 = 1 場面:場面名＋ID(マウスを乗せると「いつ鳴るか・呼び出し元・今の仮音」)/A・B・C の各候補(▶ 試聴＋候補名。マウスを乗せると説明と長さ)/選択ボタン **A・B・C・なし・作り直し** の 5 択/メモ欄(1 行)。
  - 選んだ行は色が変わる(A/B/C=金、なし=灰、作り直し=橙)。A/B/C を選ぶとその候補のセルも縁取りされる。同じボタンをもう一度押すと選択を外せる。
  - 上部(固定):進捗「選択済み n / 69」と「要再選択 n」、「未選択だけ表示」フィルタ(未選択と要再選択の行だけ残す。章が全部済むと見出しも隠す。状態は localStorage に覚える)、■停止、保存状態。
  - 旧ボードの「書き出し/コピー/ファイル保存」は、下の折りたたみ「予備:書き出し」に格下げ(新形式で出す)。wav 書き出しと「3 つ続けて聴く」は外した(P4b は `sound_lib.js` を直接使うので不要)。
- 幅 860px 未満では表を縦積みに崩す(スマホでも押せる)。この崩し方は目視していない。

## 2. 自動保存の流れ
1. 読み込み:`fetch('./sound_choice.json', { cache: 'no-store' })` が取れればそれが正。取れなければ localStorage(`nolife2.sound_choice.v2`、無ければ P4a の旧 `v1` = `{ 場面: 'a' }` も読んで大文字に直す)。
2. 選択・メモを変えるたびに localStorage へ即書き、**0.5 秒デバウンス**して `POST /api/sound_choice` に `{ "_note": …, "choices": {...} }` を送る。送信中に変更が来たら送り終わってからもう一度送る。ページを閉じる時に未送信があれば `sendBeacon` で送る。
3. 右上に「保存済み 12:34:56」(緑)/「保存待ち…」/「保存に失敗 時刻(このブラウザには残しました…)」(赤)。
- 形式は今のまま:`choices[scene] = { pick: 'A'|'B'|'C'|'none'|'redo', note? }`。並びはゲーム順。選択を外してメモだけ残した行は `{ note }` だけ(pick なし)になる — P4b は pick の無い行を「未選択」と扱えばよい。表に無い場面 ID の記録が入っていても消さずに残す。`_note` は読み込んだものをそのまま保つ。
- 検証用 `window.__SB`(この盤だけ):`doc()`・`serialize()`・`saveLog`・`loadedFrom()`・`flush()`・`check({ ids, from, to, live, rate })`。

## 6. 判断と申し送り
- 「未選択」には作り直し済みで redo のままの場面も含めた(ユーザーが選び直す必要があるため)。進捗の「選択済み」はそれを除いた数。
- 選択の取り消し(同じボタンをもう一度押す)を入れた。押し間違いの戻し用。
- spaces の性能テストと enemy 21 は内蔵ペインが表示されている状態での再計測をメインで。今回の環境では HEAD でも同じ結果。
- `docs/p4a/sounds.md` は指示の範囲(pl_crouch の廃止注記・作り直しの履歴 1 行)に加え、作り直した 2 場面の行の候補説明と `x312_dive` の説明(「しゃがみ長押し」→「Ctrl 長押し」)を新しい中身に合わせて直した。冒頭の旧形式の説明文(`{ 場面 ID: "a" }`)は残し、履歴行で新形式を書いた。
- P4b:`sound_choice.json` の pick は大文字(A/B/C)。`sound_lib.js` の候補 id は小文字なので、引く時に小文字へ。pick の無い行(メモだけ)と `redo` は鳴らさない扱いでよい。
