# P5b-5 管理人の手の修正 — 引き継ぎメモ

## 1. 原因
- レスト（MakeHuman の A ポーズ）は指が扇状に開いている。手の軸（手首→中指の付け根）に対して、人差し指 +4°・中指 -9°・薬指 -20°・小指 -29°（全体で 33° 開く）。ここに Mixamo の指の曲げが乗るので、曲がるほど指先が掌の中心へ寄って鉤爪になっていた。
- P2a の右手の握り `apply_grip` は、曲げ軸を「骨の Y 軸 × 掌の法線」で出していた。ところが FBX を `automatic_bone_orientation=False` で読んでいるため、指の骨の Y 軸は指の向きではなく、ほぼ上向き（アーマチュア空間 +Y）になっている。そのため曲げの向きがずれ、人差し指が柄に沿って伸びたままになっていた。開きも閉じていなかった。
- ハンマーの握りの点（P2a）は「掌の中央（手首→中指の付け根の 75%）から掌側へ 2.5cm」で、拳の中心より約 2cm 手首寄りだった。ここでは指が柄を包めない。
- `.blend` のハンマー（レンダ用）は、ゲームと向きが違っていた。読み込み時の軸変換（glTF→Blender）と、P2d で入れた `hammerFlipAxis` が反映されておらず、柄が掌の法線方向を向いていた。P2a の静止画のハンマーはゲームの向きと一致しない。

## 2. 直し方（`tools/blender/mixamo_merge.py`）
- Mixamo の指アニメは使わない。両手の 5 指 × 4 節（計 40 骨）を、全 14 アクションで定数キー（CONSTANT）に置き換える（`bake_hand_pose`）。
- 姿勢の計算は `hand_pose(arm, side, HAND_POSE[side])` で行う。レスト基準・アーマチュア空間。
  - 握りの軸 `across` = 小指の付け根 → 人差し指の付け根。柄と懐中電灯はこの向きに通す。
  - 掌の法線 `n` = across × (手首→中指の付け根)。親指のある側が正になるように符号を合わせる（左右で外積の向きが逆になるため）。
  - 握りの点 = 中指の付け根 + t0·u + e2·v。t0 は掌の面内で軸に直交する向き、e2 は軸と t0 に直交する掌側の向き、(u, v) は `grip_uv`（cm）。
  - **開きを閉じる**：各節を `n` まわりに回して、t0 から spread（人差し指側が正）の向き t に揃える。
  - **曲げ**：曲げ軸は a = t × n（開きを閉じた後の向きで計算）。MCP=θ1・PIP=θ2・DIP=dip×θ2 とし、掌の面からの累積角で合わせる。θ1・θ2 は 2° 刻みで探してから 1° 刻みで詰める。評価は、PIP・DIP・指先・各節の中点が軸から R の距離に並ぶほど良く、R より内側（めり込み）は 20 倍で罰する。
  - **親指**：付け根の節の向き（方位・仰角）と MP 屈曲 φ（IP=0.8φ）を格子で探す。指先の目標は「中指の末節の中点から、軸と反対側（拳の外側）へ 2cm」。末節は軸の小指側へ向ける。円柱・人差し指・中指へのめり込みは罰し、付け根の節はレストの向きから大きく離れないようにする。各節の回転はレストの向きから目標の向きへの最小回転。
  - 骨ごとの局所回転は L_j = R_j⁻¹ · D_{j-1}⁻¹ · D_j · R_j。R_j は骨のレスト姿勢（matrix_local）、D_j はその節のアーマチュア空間での回転で、D_0 = I。4 番目の骨（指先の端）は単位回転にする。
- ハンマー：握りの点を右手の「指の輪の中心」に変えた（`hammer_matrix`）。向き（quaternion）は変えていない。`.blend` 側はゲームと同じ向き（K⁻¹・Fx を挟む）にそろえた。
- 懐中電灯：左手の輪の中心と輪の軸を、meta の `flashlight_grip`（LeftHand の GLB 局所座標）に記録する。

## 3. 生成とハンマー位置の差分
- merge は `tools/build_enemy_rigged.sh` と同じコマンドで実行した。ただしレポートは `docs/p5b5/check.json` に出した（既存の p2a の docs を上書きしないため）。静止画（p2a）は再生成していない。結果は 20/20。新しいチェックは「両手 40 骨を焼いた」と「握り：指の関節と軸の最短距離」。
- `node tools/check_enemy.mjs` は OK（アクション 14・形状キー・骨 65・door_open_in の移動 1.791m）。
- meta の hammer：position_m が [0.006118, 0.098233, 0.025449] から [0.01063, 0.119308, 0.023517] に変わった。骨の向きに 2.1cm 先へ（指先側へ）動いた形。quaternion は前と同じで [0.005073, 0.000799, 0.778998, 0.627005]。`src/enemy.js` の `ENEMY.hammerPos` をこの値に更新した。
- `src/enemy.js` の懐中電灯：これまでは手首（LeftHand の原点）に本体の中央を置いていた。今回、`ENEMY.flashlightGrip`（meta の値）で左手の握りの点を求め、本体の z=-0.06 をそこに合わせるようにした（group の原点 = 握りの点 + 光の向き × 0.06）。向きはこれまでどおり進行方向・aimPoint に合わせる。光の筋が内側にあるかの判定の基準点は、手首から group の原点に変えた。
- `build/enemy/` は gitignore なので、GLB・meta・.blend はコミットしていない。再生成は `tools/build_enemy_rigged.sh` の 1/2 merge で行う。

## 7. 申し送り（ユーザー判断待ち）
- 312 の立ち姿勢を直すなら、次のどちらかが必要：
  - ① `poseManager('stand')` で腕の骨に回転を足し（肘を伸ばし、上腕を下ろす）、静止姿勢を作る
  - ② Mixamo から腕を下ろした idle（例：直立して待つ系）を追加で取る
- 懐中電灯は「握りの点で握る」だけで、向きは光の向き（進行方向）に従う。腕の振りが大きいクリップでは、本体と拳の軸がずれる瞬間がありうる（角度は未計測。撮った 3 場面では目立たない）。拳の軸に完全に固定すると、光の筋が腕と一緒に振れるので今回はやめた。
- `docs/enemy-candidates/p2a/` の静止画は旧い手・旧いハンマー向きのまま（既存 docs なので再生成していない）。`build_enemy_rigged.sh` を走らせると p2a の静止画と check.json が新しい手で上書きされる。
