## 2. 階の GLB の構成（`tools/blender/build_floor.py`）

階ごとに `build/floor_N.glb`・`floor_N_lightmap.webp`（2048px、WebP q92）・`floor_N_manifest.json`（N=1..7、7F は屋上B込み）。

- 入力は `building.json` の `floor.shell`（`build_building.mjs` の `shellFor` が書く）:
  - `air`: 歩ける/見える空気の矩形（重ならない）。`kind` で仕上げが決まる — corridor/hall（長尺シート・クロス・天井材）、lobby（石目タイル床・濃灰のタイル壁・暗い天井）、theater（暗いカーペット・暗い壁）、room（食堂）、alcove（EV 扉の凹み）、outdoor（外階段の踊り場）、well（階段の吹き抜け。壁は階高いっぱい）、stair（北階段の踊り場）、room410
  - `caps`（410 の闇の板）・`windows`（夜空の発光面）・`lights`（ダウンライト・壁付け灯）・`exits`（非常口サイン）・`operable`（開く扉）・`hideSpots`（管理人の潜伏場所）
- 壁: walls.js と同じ箱（Python 移植）を、同じ線上で重なる/接するものを1本にまとめ（Z ファイト防止）、空気に接する部分へ切り詰めて、空気に面した面だけを 0.25m 刻みで種類判定して張る。屋外に面した面は「裏が建物なら外壁（コンクリート）、建物が無ければ手すり（面を張らない）」
- 扉: 居室＝茶の木目＋号室プレート（`build/tex/room_plates.png` のアトラス）＋覗き穴。施錠扉は室内側の面を張らない（ライトマップ節約）。鉄扉（外階段・北階段）・共用扉（食堂・シアター）・風除室の自動ドア（ガラス2枚が左右反対へ。`n2_kind: autodoor`）
- EV: P0b の `p0b_ev.py` をそのまま全階で使用。呼びパネルの階数表示はアトラス（`ev_display.png` の1〜8）の UV をその階へずらす。カゴの左袖に行き先ボタン盤（`ev_car_panel.png`、ボタンの世界座標を manifest `evButtons` に）
- 外階段: 階の踊り場→上りレーン→中間踊り場→下りレーン→上の階の踊り場まで（縞鋼板・角柱・縦格子の手すり・壁付け灯）。1F は東レーンの下が地面（低い手すりで塞ぐ）。7F は屋上B の踊り場まで。上の階の踊り場の床は「ベイク専用の遮蔽」（`n2_bake_only`、書き出さない）
- 屋上B: 防水シート床・パラペット（0.75m）＋手すり・EV 機械室・受水槽・点検口・室外機5台・壁付け灯2つ
- ベイク: P0 と同じ `bake.py`（Cycles・Metal・1024spp・OIDN）。隣の階の階段の灯りもベイクにだけ入れる（階段で明るさが繋がるように）。屋外は空を弱く（`--sky 0.03`）
- 書き出し: `export.py --images NONE`（**テクスチャを埋め込まない**）。材質→実行時テクスチャの対応を manifest `materials` に書き、ブラウザ側（`src/world.js`）が `build/tex/` の共有ファイルを貼る

## 3. 読み分けの仕組み（`src/world.js`）

- 当たり: 全7階＋屋上B（キー `'RB'`）の箱を起動時に全部作って常駐（`world.collisions(key)`）。EV はシャフトの塊をカゴの殻（前壁・扉 `evdoor`・側壁・奥壁）に置き換えて中に入れる。階段は段の手前の当たり（`stairguard`）
- 見た目: `world.focus(key)` が「居る階 ±1」を非同期で読み、それ以外を解放（geometry・material・ライトマップを dispose。共有テクスチャは残す）。読み込み中は描画しないだけで、当たりは常に有効なので落ちない
- 見せる階: ふだんは今の階だけ。外階段・北階段の区画にいる時と上り下りの最中だけ上下の階も見せる
- 扉の状態（角度・施錠・当たり）は全館ぶん `world.doors` に常駐し、GLB の扉板は読み込まれた時に結び付く（解放しても状態は残る。4F を読み直したら 410 の室内側ドアスコープも付け直す）
- 静的メッシュは階ごとに材質単位で結合（P0 と同じ）。動くのは開く扉・EV 扉・自動ドアだけ

## 4. 移動

- **EV**（`src/elevator.js`）: ホールの呼びボタン（E）→カゴが来て開く→乗って行き先ボタン（視線の先のボタンで E、または数字キー 1〜7）→閉まる→移動（WebAudio の仮音: モーターの唸り・チャイム・扉）→行き先で開く。移動は「到着時に同じ場所の行き先の階へ移す」（カゴの見た目は全階に同じものがある）。行き先が読み込み終わるまで到着しない。カゴの照明は使っている時だけ点灯（PointLight 1 灯・影なし）
- **外階段・北階段**（`src/stairs.js`）: 踊り場の「段の口」（各レーンの手前 0.6m）に入って段の方へ W で、段に沿って1層ぶん自動で上り下り（視線は進む向きへゆっくり寄る・マウスで見回せる）。外階段は 1→…→7→屋上B、北階段は 1→2→3
- 画面ガイド（`hud_text.js` に追加）: 「E 呼ぶ」「E N階へ」「1〜7 行き先」「W 上の階へ / 下の階へ / 屋上へ」、呼んだら「エレベーターを呼んだ」

## 5. 管理人（`src/enemy_ai.js`・`src/ai_graph.js`）

- 移動グラフは全7階を常駐（`buildAIGraph`）。4F は P0 の点（N0・C1〜C5・J・JE・EV・R）を同じ名前と座標のまま残し、横廊下・外階段の踊り場を足した。他の階は `L:名前`（縦廊下 2.9m おき・横廊下・EV・踊り場・北階段・1F 共用部）。扉をまたぐ辺は扉の中心線の前後に点を置く（体の半径で枠に掛からない）
- 管理人は `ai.level` の階で動く。プレイヤーと別の階の間は見えない・聞こえない（物音は同じ階だけ）。経路が階をまたぐと `_transfer`（待つ→姿を消す→移動時間→次の階の同じ点に現れる）。読み込まれていない階にいても当たりはデータから取れるので論理はそのまま進み、描画だけしない
- 潜伏場所は各階の `shell.hideSpots`（4F は P0 の4か所が先頭）。プレイヤーが別の階なら半分の確率でその階へ移って潜む
- 鍵で開けて入る・覗き穴・スコープ演出は 4F の 410 だけ（P2 のまま）

## 6. ビルド手順

```
tools/build.sh                 # 全階(1〜7)。building.json 生成 → build/tex → 各階 build_floor → bake → WebP → export → check_glb
tools/build.sh --floor 4       # 1 階だけ
tools/build.sh --samples 256   # 試し焼き(既定 1024)
node tools/check_glb.mjs       # 機械テストだけ(--floor N / --verbose)
```
1 階あたり約 1 分（M4・Metal・1024spp）。中間物（`build/floor_N_scene.blend`・`_baked.blend`・`_lightmap.png`・`build/logs/`）は .gitignore。

## 9. 既知の課題

- 管理人の EV 利用は扉の演出なし（ホールで待って姿を消し、行き先の EV 前に現れる）。プレイヤーのカゴとは独立
- 屋上B・外階段の上り下りの途中には管理人は来ない（移動グラフは各階の踊り場まで）
- 正面玄関（外側の自動ドア）は夜間閉のまま。外は暗い背景の板だけ（外観・外環境は P3c）
- 施錠扉（結合済み）はノブを鳴らしても扉板は揺れない（音と「鍵がかかっている」の表示だけ）
- ガラス（風除室）に懐中電灯を近距離で当てると白くにじむ
- 扉の上の垂れ壁と壁の境にライトマップの継ぎ目が少し見える。EV のアルコーブの袖を近くで見ると影の境がギザギザ（ライトマップの解像度。カゴの内装と三方枠はライトマップを使わずカゴの照明で見せている）
- 横廊下の北側（西棟と東ブロックの間）は図面どおり居室が無いので、長い無地の外壁になる（窓は P3c の外観と合わせて検討）
- `?test=enemy` の 11 番（画面ガイド）の EV の期待値を「反応がない」→「エレベーターを呼んだ」に更新した（EV が動くようになったため）
- 旧 P0 の `build/p0.glb`（35MB、埋め込みテクスチャ）はリポジトリに残っているが読み込まない（`tools/build.sh --p0` で再生成可）

## 10. 監査対応（2026-11-01）

### 10.1 カゴの行き先ボタン盤が鏡文字だった
`build_floor.py build_car_panel` の UV が左右逆（左袖の壁を向いた人の右は奥 +d なのに、扉側へ u を増やしていた）。UV とボタンの世界座標（manifest `evButtons`）の両方を +d 向きに直して全階を再ベイク。`?test=building` に「4F で視線の先の『5』を E → 5F に着く」（`3b_ev_button_5`）を追加して通過（8/8）。スクショ `p3a_ev_car.jpg` を差し替え。

### 10.2 fps の切り分け
内蔵ブラウザの枠が非表示の状態でしか測れず（rAF が止まる）、代わりに GPU のタイマー（`EXT_disjoint_timer_query_webgl2`）で 1 フレーム（全ポスト込み）の GPU 時間を測った。描画バッファ 1539×1346、4F 廊下(6.9, 7.6)南向き、管理人は EV ホールで歩行アニメ・懐中電灯 ON、30 フレーム × 5 回を条件を交互に入れ替えて中央値。
同じ測り方で P2e（コミット 58dea07 を別ポートで起動）も測った。非表示の枠では GPU のクロックが下がるようで絶対値は大きめに出る（P2e は実機 60fps でも 21ms と出る）ので、**P2e 比**で見る。

| 条件 | GPU ms（中央値） | P2e 比 |
|---|---|---|
| P2e（同じ構図・同じ測り方） | 21.0 | 1.00 |
| P3a 基準（±1 階を読み込み済み・管理人あり・プレイヤーの懐中電灯 OFF） | 19.2 | 0.91 |
| 居る階だけ（上下の階を scene から外す） | 18.7 | 0.89 |
| 管理人を描かない（?noai 相当＋非表示） | 17.7 | 0.84 |
| 管理人の懐中電灯（影付き SpotLight）OFF | 16.6 | 0.79 |
| GTAO OFF | 9.2 | 0.44 |
| bloom OFF | 7.7 | 0.37 |
| プレイヤーの懐中電灯 ON | 21.6 | 1.03 |

- 結論: GPU 時間の大半はポストエフェクト（GTAO と bloom。どちらか片方を切ると半分以下）で、これは P2e と同じ（P2e でも GTAO OFF 11.0ms・bloom OFF 10.5ms）。P3a の建物そのもの（全館のジオメトリ・上下の階）による増分は今回の測り方では見えない（基準は P2e 比 0.91）
- 照明: シーンのライトは 半球光・プレイヤーの懐中電灯（影付き）・管理人の懐中電灯（影付き）・EV のカゴの PointLight（影なし・カゴを使っている時だけ可視）の4つで、影付きは P2e と同じ2つ。増えたのは EV の PointLight だけで、ふだんは不可視（描画コストなし）
- programs 84・textures 93（P2e 51・64）の増分: 材質の種類が増えた分のシェーダ（石目・縞鋼板・ガラス・号室プレート等）と、±1 階のライトマップ2枚＋共有テクスチャ十数枚。どちらも VRAM で、毎フレームのコストではない（描画コールは P2e 229 → P3a 195 と減っている）
- 直したもの（安いもの）: 見せない階（上下の階）は `visible=false` ではなく **scene から外す**（描画リスト・影・GTAO の走査に入れない。`world.setVisible` は変わった時だけ出し入れ）。未使用テクスチャ: 解放した階の材質・ライトマップは dispose 済み、共有テクスチャ（build/tex）は全階で使い回すので保持
- 実機で 60fps を割る場合の次の手（見た目に関わるので未実施）: GTAO のサンプル 12→8 または 1/2→1/3 解像度、bloom の解像度を半分に。どちらも LOOK/パスの数値 1 か所で変えられる

## 11. P3a-2 差し戻し対応（2026-11-01）

### 11.1 風除室の質（「ガラスの光沢や作りが安っぽい」）
- **透明ガラス**: 厚み 12mm の板。表裏 `M_GlassClear` は実行時に `MeshPhysicalMaterial` へ置き換える（`world.js _prepare`。transmission 1・ior 1.52・thickness 12mm・吸収色＝薄い青緑 `LOOK.glass.tint`・粗さは指紋/拭き跡/埃のマップ `build/tex/glass_smudge.jpg`・両面）。小口 `M_GlassEdge`（青緑）。腰の高さに視認シール `M_Decal`
- **ベイク対象外**: n2_kind `glass`/`glassedge`/`decal` はベイク中 render から隠し（光を遮らない・焼き込まない）、ライトマップ UV は 0 に潰す（`build_floor.py lightmap_uvs`・`bake.py`）。実行時もライトマップを使わない（`NO_LIGHTMAP`）
- **映り込み**: 1F の manifest `envProbe`（風除室の中心・256px）。1F の GLB を読み、材質のテクスチャが読み終わった後に 1 回だけ キューブカメラ→PMREM（ガラスは隠す）。`envProbe.intensity` の材質（ガラス・ヘアライン・ステンレス・石の床と壁・ポスト・操作盤）の envMap に差す。石（非金属）は**鏡面だけ**に使う（`specularOnlyEnv`: 拡散の IBL を足さない＝ライトマップと二重にならない）。階を解放すると dispose
- **金物**: ヘアラインのステンレス（縦材 `M_HairV`・横材 `M_HairH`＝同じ粗さの筋テクスチャを UV 入れ替え）。自動ドアの扉板＝ガラス＋上下の框＋縦框、固定ガラスより 7.5cm 手前を滑る（固定ガラスと同じ面で重ならない）。ガラスの線の上は全幅の無目（駆動ボックス）、開口の中央に黒いセンサー（両面）、床に下部レール、固定ガラスの下に沓摺、端と開口脇に方立（`build_auto_door`・`build_glass_line`）
- **床・壁・天井**: 石目タイル（明るい灰・粗さマップ 0.2〜0.4・法線）、濃灰の大判タイル（御影石調の粒・目地）、天井は少し明るい灰。ロビー・風除室・メールコーナーのダウンライトは 4.5W（廊下の常夜灯より明るい。写真は夜の撮影で明るい）
- **外側ドアの先**: 庇の下の石の床・庇の天井にダウンライト 2 灯・左右の石の外壁・その先は暗いアスファルト（`build_porch`。旧「暗い街路の発光板」は撤去。外へは出られない）
- **宅配ボックスの壁・管理室の小窓・操作盤**: ポストの面を 2048px に描き直し＋扉の隙間の法線マップ・台座と見切り・床の点検口の枠／小窓はヘアラインの額縁＋ガラス（物理材質）＋奥の暗い事務室＋受け台と書類／オートロックの操作盤（風除室の西壁）
- 性能: 透過(transmission)は風除室が画面に入っている間だけ背景をもう一度描く。内蔵ブラウザ(枠非表示・1920×1080・GPU タイマー中央値)で風除室を見た時 物理ガラス 17〜23ms / 従来の半透明 10〜12ms(+約 8ms)→ `renderer.transmissionResolutionScale = LOOK.transmissionScale = 0.5` で +2〜3ms(13〜16ms)。風除室が画面外(1F 廊下)では差なし。実機で重ければ 0.35 へ
