### #2 階段の発動（視線でなく移動）

- `src/stairs.js` の `update`: 段の口の中で数える。
  - 向きは「動かそうとした移動の向き」で見る（`player.wish` = WASD の合成。当たりの前の 1 フレームの移動）。
  - 流れ（+s）との dot が 0.7 未満の移動は累積を 0 に戻す（横切る・戻る・扉の方へ歩く）。
  - 進んだ距離は前フレームとの差の流れ成分で足す。
  - 0.35m で `start`。
  - 口から出る・別の口（上り/下り）に移る・1 フレームに 0.5m 以上動く（テレポート）とリセット。
  - 止まっている間は累積を保つ。
- 段の手前の当たり（stairguard。s0＋0.3）に押し付けている間（実際の移動が意図の半分未満）は、押している移動量で数える。理由は §3 の 1。
- `STAIRS.forwardDot` を `flowDot 0.7`・`flowDist 0.35`・`jump 0.5` に置き換えた。
- `start` の時の累積は `stairs.lastStartAcc` に残る（テスト用）。
- `STAIRS.exits` は変えていない。到着位置はもともと口の外（§3 の 2）。
- `main.js` は `__N2.stairsArrival`（`arrival` の export）を出す。

### #3 鎖と、異空間から出た後の管理人

鎖:
- 対象の扉は `CHAIN_DOORS` = MST1〜7・NST2・NST3。
- 期間は `story.chained` = play で、第3段〜第9段（第9段の `sub === 'chase'` を除く）。
- `_updateChains()` は毎フレームと `applyStage` で呼び、変わった時だけ切り替える。
  - かける時: 扉の `chained`・`locked`・`storyLock` を立て、閉じた姿勢（angle 0・当たり有効）に戻す。開いていた扉も閉じる。
  - 外す時: 3 つとも下ろす。
- `storyLock` を立てるので、管理人の `_doorEntry` も開けない。`doorApi.open` も鎖の扉は開けない（`main.js`）。
- 画面ガイドは `story.target()` の `sk: 'chain'` で「鎖がかかっている」を出す（`hud_text.story.chained`）。
  - E で `rattleChain`: 一時表示、`enemyAudio.play('rattle')`（rattle は「なし」の採用なので記録だけ）、扉の小さな揺れ。
  - `main.js` の `useNearestDoor` にも、鎖の扉なら `rattleChain` を呼ぶ保険を入れた。
- 小道具は `story_props.makeDoorChain(width, half)`。
  - 扉の両面に鎖 2 本を X に掛け、枠の外 6cm に金具、交点に南京錠（自作の `makePadlock` の 2.2 倍）。
  - 鎖の環はまとめて 1 つの形にしている（扉 1 枚につき描画 1 回＋南京錠）。
  - 表示はその階にいる時だけ（1F の扉は敷地からも）。
- 第9段の追跡の開始（地下の鍵）で外れる。死亡しても `sub` は残るので外れたまま。`applyStage(9)` ではまたかかる。

異空間から出た時:
- `story.leaveSpace` → `_afterSpaceExit(space, back)` で次を行う。
  1. `chaseOmni` を解く。
  2. 管理人が次のどれかなら、出た階でない EV ホール（4F。出た階が 4F なら 5F）へ `reset` する（PATROL）。
     - 異空間か出た階にいる
     - EV で移動中
     - 出た階へ向かっている（`ai.goalLv`。`_goTo` が記録する）
     - CHASE・APPEAR・ALERT・ATTACK のどれか
  3. `ai.avoidFloor(back, 30)` を呼ぶ。
- `enemy_ai`:
  - `avoidFloor` / `_avoided`。
  - `floorWeights` は避ける階を 0 にする。`_chooseFloor` は重み 0 の階を乱数 0 でも選ばない。
  - `floorNoise` は避ける階の物音で動かない（`floor_noise_avoided` を記録）。
  - `applyStage` は猶予を消す。
- 例外: 第9段の最終追跡で X705 から出た時は何もしない（`space_exit_chase_kept`）。§3 の 3。
- `main.js` の `story.onAIReset(lv)` は階を受け取る（省略時 4F）。

### #4 走りの足音

- `main.js` の `stepSurface()` で面を判定する。

| 面 | 場所 |
|---|---|
| room | X312、居室の矩形の中（バルコニーを除く） |
| hard | 敷地 G・屋上B・B1・XB1・X705、外階段・北階段・地下階段の区画（`inStairArea`）、上り下りの最中、バルコニー・屋上A（`outdoorKind`） |
| corridor | 上記以外（廊下・EV ホール・共用室・X105） |

- 鳴らし方:
  - 歩き: room だけ鳴らす（従来の 0.75）。
  - 走り: room は 1.0、corridor は `{ cutoff 1200, vol 0.6 }`、hard は `{ highpass 300, dur 0.12, vol 0.8 }`。素材は `pl_step_room`（新しい wav なし）。
- `audio_bank`:
  - `o.highpass`（BiquadFilter highpass・Q 0.7）を足した。
  - `o.dur` で切る時は尻 25ms を落とす（クリック対策）。
  - 記録に `tag`・`cutoff`・`highpass`・`dur` を残す。
- 管理人の聴覚（`enemy_ai` の走りの音）は変えていない。

## 3. 判断と既知の妥協点

1. **#2 の「前フレームとの差」は、口の奥の当たりに押し付けた時だけ「押している移動量」で数える。**
   - 段の手前の当たり（stairguard）は s0＋0.3 から始まり、体の半径 0.28 を引くと口の中で前へ進めるのは最大 0.62m。
   - 口の途中から入る、ドア枠に擦れて斜めに滑る、といった時は、実際の差だけだと 0.35m に届かず、W を押しても下りられない状態になった（1c の再現で 0.348m で止まった）。
   - 向きの判定は移動の向き（WASD の合成）なので、視線・見るだけ・横切るだけでは始まらない、は保っている。
2. **外階段の各階（2〜7F・RB）は、鉄扉そのもの（z 21.2）が口の帯（s0−0.6＝21.15 から s0＋0.35 まで）の中にある。**
   - そのため、どの到着位置からでも扉の直前 0.7m は口に入る（直線上 41 点のうち 6 点）。到着位置（`STAIRS.exits`）を動かしても解けないので変えていない。
   - 到着 → 扉へ下を向いて歩いても始まらないことを全停留所で機械テストした（扉へ向かう移動は流れとの dot が 0.35 程度）。
   - 北階段の 1F は扉が無い（向くだけの点は建物の壁の向こう）ので、重なりの判定から外した。
3. **#3 の「異空間から出たら追って来ない」の第9段の扱い。**
   - 第9段の最終追跡（地下の鍵の後に 705 から出る）は、§3.10 の表の第9段「従来どおり。追跡の開始で鎖が外れる」に合わせて、管理人が 7F へ追ってくるままにした。
   - #3 の文言の「705 から出た時」は、追跡の前（鍵を取る前）や第10段以降の出入りに効く。
   - story 9 番（管理人も 7F に出てくる・階段で追う）は従来のまま通る。
4. 管理人を「別の階へ」移すのは、出た階・異空間にいる、または追跡・警戒中などの時だけ。他の階で潜伏中ならそのままにして、避ける階の設定だけ入れる。
5. 鎖をかける瞬間（第3段の開始）は扉を閉じた姿勢へ瞬時に戻す。プレイヤーは 1F の管理室にいるので見えない。
6. 地下の口の天井灯は踊り場の中ではなく開口の通路側に置いた（§1 #5）。
7. PointLight 2 灯は 1F・B1 にいる時だけ出すので、階が変わるとライトの数が変わってシェーダの組み合わせが切り替わる。
   - EV のカゴの灯りと同じ扱い。初回だけ切り替えのコンパイルが走る可能性がある。
8. 鎖の音は既存の `rattle`（採用は「なし」＝無音で記録だけ）。音を足すなら P4 系で `door_locked` の選択から。
9. 312 の R5 の鍵は見た目の札が「玄関」になっただけで、位置・拾える条件は従来どおり。
