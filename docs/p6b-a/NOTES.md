## 1. 項目ごとの実装

### #1 全室スコープ
- `main.js`
  - `PEEP_ROOMS`: 内装のある 1K（`kind 'unit'`・`door.enterable`・`interior`）。食堂・シアター・管理室・別空間は入らない。
    - building.json の該当は **36 室**（契約の「33 室」と数が違う。§6 の 3）。
  - `lensFor(rid)`: レンズの位置と向き。
    - 位置: 扉板の廊下側の面（扉の中心・床から 1.48m）の 1.5cm 外。扉の facing の法線方向へ raycast して求める。
    - 向き: 廊下を向く（`yaw = atan2(−nx, −nz)`）。
    - 扉板が読めていない・開いている時は、当たりの箱の廊下側の面で代用する。
    - 扉板で測れた結果だけキャッシュする。410 は従来の値と同じ（x 7.785・z 7.25）。
  - `canPeep()`: 次をすべて満たすと覗ける。
    - 覗き穴のある部屋の矩形の中（バルコニーは除く）
    - 扉面からの奥行きが 0〜1.0m
    - レンズまで 1.2m 以内
    - 扉に正対している（内積 > 0.5）
    - 扉が閉じている
  - 覗く時（E 長押し・P・`__N2.peephole(true)`）は、今いる部屋のレンズへ差し替える（`peephole.setLens`）。
    - 閉じたら 410 に戻す。チュートリアルの強制の覗き穴は 410 のまま。
  - 室内側のドアスコープ（真鍮のリング）は 1 組だけ持つ。プレイヤーが入った部屋の扉板へ付け替える。
    - 扉の向きに合わせて回す。廊下からは扉板の裏で見えないので、全室に置く必要はない（描画コールは増えない）。
  - `inRoom410` は 410 固有のまま残した（hud は使っていない）。
- `enemy_ai.js`
  - `SCOPE` の発火条件を一般化した。`knownRoomId` が今いる部屋で、その部屋が `peepRooms` にあり、管理人が同じ階の廊下側にいる時に発火する。
  - `_scope(opts.room)` の立ち位置は `_scopeGeom(rid, side)` で扉ごとに出す。距離は 410 の実測値と同じ:
    - 起点: 廊下の中心（扉面から 0.9m）で扉から 2.35m
    - 終点: 反対側へ 0.75m
    - 隠れる所: 扉面から 0.38m・扉から 1.05m
    - 覗き込む所: 扉面から 0.44m
  - 管理人のいる側の起点か隠れる所が廊下の外（壁・部屋の中）なら、反対側から通る。
  - 覗き込む時の頭の合わせ（法線方向と横方向）は、410 で旧式と同じ式になるように書き直した。
  - hide roll・ノブ・扉を開ける処理は `rid` を使う。
  - 巡回でプレイヤーのいる覗き穴の部屋の前に来た時の「体を回さない見回し」も、410 と同じにした。
  - 410 固有で残したもの: `ROOM_POINT`、`P0_ORDER`、`r410_*` の隠れ場所、グラフの `'R'` ノード、`_leaveRoom` の既定値、`CHECKPOINT`、`ENEMY_HOME`。

### #3 空室潜伏の光・体の漏れ
- **実測**（`_lurkRoom` を 1 フレームずつ。見えている部分の AABB は SkinnedMesh をスキニング後の頂点で、ハンマー・懐中電灯を含めて取った）:
  - 通常の入室では、懐中電灯は扉を開ける前に消えていた（光の筋は出ない）。
  - ただし `inside 0.5` で扉に向き直って閉める間、ハンマーが閉じていく扉板を抜けて廊下側へ最大 +8.7cm 出た（扉 0.14rad の時）。
- **真因（筋の正体）**: 管理人が空室（例 3F 310）に潜んで扉を閉めた後、向かいの入れる部屋（305）でプレイヤーが懐中電灯を点けると、次の連鎖が起きていた。
  1. 光漏れの判定（`_updateRoomKnowledge`）が「管理人は廊下側にいる」と誤認した。空室は `_rid` に無いため。
  2. `_learnRoom` → `setState('ALERT')` で、閉じた空室の中で concealed が外れた。
  3. 懐中電灯が点いた。光の筋の円錐は扉を抜けて廊下側へ +0.3〜0.5m 出た。閉じた空室の扉板は P5a で影のパスから外してあるので、スポットの光も扉を素通りした。
  4. 管理人は扉に押し付けて `stuck` を繰り返した。
  - 3F は 305 と 310 が向かい合っている（ユーザーのスクショの階）。
  - 同じ形で引き出す経路は、ほかに 3 つあった:
    - 物音（`noiseRoom`）
    - クローゼットに隠れた（`LOCKER`）
    - 覗き穴（`SCOPE`。#1 で全室になり経路が増える）
- **直し方**
  - 空室の中に潜んでいる間（`LURK` かつ `lurkRoomId`）は、`setState` が非強制の状態変更を `_lurkWake = { state }` に預ける。
    - その後 `_roomRelease` で静かに扉を開けて出て、扉を閉めてから預けた状態へ移る。
    - そのまま通す状態: 強制（物語・テスト）・`ATTACK`（飛び出し）・`EVAMBUSH`・`APPEAR`・`INTRO`・`SCRIPTED`・`DEAD`。
  - 閉じた空室の中からは、光漏れと入室の目撃を見ない（`!this.concealed`）。物音は聞こえるので、出てから向かう。
  - 入る途中（扉を開けてから閉めるまで = 割り込み不可）に知った時も、閉め終えてから出て探しに行く（`_learnRoom` → `_lurkWake`）。
  - 出て行く途中に来た `pending` は、`PATROL` で上書きしない。
  - 入室の順序: 消灯（開ける前）→ 開ける → 扉面から **1.3m**（`roomLurk.inside` 0.5→1.3）まで戸口の中心線に沿って入る → 扉を向く → 閉める → 閉まり切ったフレームで concealed。
    - 最後の concealed は `ai.afterDoors()` が行う。main が扉を動かした後・描画の前に呼ぶ。以前は 1 フレーム遅れていた。
- 実測（直した後。3F の 4 方向の扉）:
  - 扉が開き始めてから潜むまで、懐中電灯は 0。
  - 中に収まってからの突出は最大 −0.024m（廊下側へ出ない）。
  - 閉める間は扉面から 1.30m。AABB の最も扉寄りは −0.70m。
  - 閉まり切った時に concealed。stuck は 0。

### #9 管理人のいる階へ EV で降りる
- `elevator.js`: カゴが動き出す時にプレイヤーが乗っていれば、`onPlayerRide(to, { from, eta })` を呼ぶ。`eta` は扉が開き始めるまでの秒（1 階差で 4.7 秒）。
- `main.js`: `ai.evRideCheck(to, info)` を呼ぶ。見学モードとチュートリアル中は呼ばない。
- `enemy_ai.js` の `evRideCheck`
  - 対象: 管理人が `to` の階にいて、状態が `PATROL` / `ALERT` / `SWEEP`、廊下の角の潜伏、空室へ向かう途中のどれか。
  - 対象外: 空室の中・`INTRO`・`SCRIPTED`・`CHASE`・演出中・割り込み不可・移動中・眠っている（第 1 段の 2F 待機）。
  - 対象なら `EVWAIT` に入る。
- `EVWAIT` の流れ:
  1. EV ホールの扉の中心から 1.2m（ホール側）・扉を向く位置へ、経路で 1.35 m/s で歩く。歩いている間は消灯。
  2. チャイム（`arrived`）までに着かなければ、その時に立ち位置へ移す。扉は閉じているので見えない。
  3. 扉が開き始めたら点灯し、視点を固定する（`onViewLock`・戻さない → 襲撃ムービーへ引き継ぐ）。
  4. `open ≥ 0.55` で 4.0 m/s で詰めて `ATTACK`（EV の賭けの near と同じ）。
  - カゴが来なければ 40 秒でやめる。
- 実測（3F の廊下・4F のカゴから）:
  - 近い（z 17）: 歩いて着く。
  - 遠い（z 3）: チャイムで移る。
  - どちらも、扉が開き始めた時に扉の正面 1.2m にいた。開き始めから 2.25 秒で OUT。

## 6. 判断と申し送り

1. **`?test=audio` 5b・10 は #2 の仕様と食い違う**（`test_audio.js` は A レーンの編集範囲外なので、触っていない）。
   - 5b は「焦らしの間に enemy_breath_close が鳴る」を `closet: 0`（spare）で確かめている。#2 では spare は無音になった。
   - 10 は、5b でしか enemy_breath_close を呼んでいないので連鎖して落ちる。
   - 直す案: 5b を `setHideOdds({ enter: 1, closet: 1 })`（open）にして、`locker_found` の後に 1 回鳴ることを見る。#2 の保証そのものは `?test=enemy` 39 にある。
2. **閉じた空室の中からは光漏れ・入室の目撃を見ない**ことにした。
   - 契約の「光漏れ」は「管理人が廊下側で扉から 6m 以内」が条件。空室の中は廊下側ではない。
   - 物音（落ちる物・走る音）は聞こえる。その場合は静かに出てから向かう。
3. **覗き穴のある居室は 36 室**（契約の文言は「1K 33 室」）。
   - building.json の `kind 'unit'`・`enterable`・`interior` をすべて対象にした。221 と 6F の罠の部屋も含む。
   - 外すべき部屋があれば、`main.js` の `PEEP_ROOMS` と `enemy_ai.js` の `peepRooms` の条件で外せる。
4. 他スイートの落ち（spaces B1_1・B1_3、building 10）は A を外した複製でも同じ（§3）。B1 は B レーンの #13 の作業中。
5. #9 の待ち構えで対象にしたのは、PATROL / ALERT / SWEEP / 廊下の角の潜伏、それに**空室へ向かう途中の潜伏**（まだ廊下を歩いている）。
   - 契約の列挙にこの最後のものは無い。足したのは、廊下側にいるので。
   - 待っている間は消灯して立つ。扉が開くとカゴの明かりと自分の懐中電灯で見える。
6. #1 の SCOPE で、管理人が扉の北側（410 なら z の小さい側）から来た時の起点は、旧 410 の 6.3（扉から 0.95m）から、南側と同じ 2.35m に揃えた。
   - 410 で北から来た時の通り過ぎが 1.6m 長くなる。
   - 起点か隠れる所が廊下の外なら、反対の側から通る（廊下の端の部屋）。
7. 一時ファイル（検証スクリプト・launch.json）はリポジトリに置いていない。
