## 2. 分割後の構造と P5b-2b への差し替え口

- `src/spaces.js`(共通): `SPACE_DEFS`(モジュールの `DEF` から世界座標の `entry`・`exit`・`at(slot)`・`back` を作る)と `Spaces`(空間ごとの ctx を作り `build` を呼ぶ・`show(key)` で `leave/enter`・`update(dt)` は表示中の空間だけ)。
- 空間ごとのモジュール `src/spaces/<key>.js` の形:
  - `export const DEF = { origin, host: { level, door }, entry: [u, v, yaw], exit: [u, v], slots: { name: [u, y, v] } }`
  - `build(ctx)`(メッシュは `ctx.group`、当たりは `ctx.cols` に push、敵の照明は `ctx.lamps` に [x, y, z])・`update(dt, ctx)`・`dispose(ctx)`
  - 任意: `enter(ctx)`・`leave(ctx)`・`exits(ctx)`(戻る口 `[{ x, z, n, auto, reach, depth, half, onLeave }]`。無ければ `DEF.exit` の扉に向かって E / 歩いて出る)・`target(ctx, look)`(空間の中の扉など。`{ d, items, use() }`)・`respawn(ctx)`(この空間で死んだ時の戻り先。null = 段の開始位置)・`entryPoint(ctx)`(入った所の上書き)・`slotPos(ctx, slot)`(動く置き場所)・`canPick(ctx, slot, cam)`・`nav(ctx, fx, fz, tx, tz)`(管理人の経路)・`debug(ctx)`
  - ctx の共有物: `scene・world・building・camera・player・ai・enemy・audio(EnemyAudio)・hud・getLevel・busy()(襲撃ムービー・視点固定・死亡演出の間)・kill(why)・story`(story は `spaces.share({ story })` で後から)
- story.js が使うのは `SPACE_DEFS[k].entry/exit/back/at(slot)` と `Spaces.show/lampsFor/exits/target/respawn/entry/slotPos/canPick` だけ。slot 名(`memo`・`key`・`desk`・`ambush`・`hook`)は維持。
- `x705.js`・`xb1.js` は P5b-1 の仮の小部屋のまま(PointLight 1 灯。最初に入る時に全材質のシェーダが作り直される引っかかりがある)。光はこの 2 空間のように**シェーダの中で計算する**と、他の材質に影響しない(three.js のライトを足さない)。
- 管理人を別空間で動かす時: `ai.appear({ level: key, … })` で現れ、`ai.chaseOmni = true` で見失わない、`ai.spaceNav`(main.js が `spaces.nav` をつなぐ)で空間の中の経路。出る時は `story.onAIReset()` で建物へ戻す。

## 3. 105 の作り

**レーン**(どれも +z へ進む。原点 x 300・z 0):

| レーン | 中心 u | v | 終わり | 始まり |
|---|---|---|---|---|
| R0 | 0 | 0〜70 | 分岐 F1(左 −1.1 施錠 / 右 1.1 → R1) | 105 の扉(戻る口。伸び始めた後は使えない) |
| R1 | 1.1 | 70〜96 | 分岐 F2(1 回目: 右 2.2 施錠・左 0 → RL / 2 回目: 左 施錠・右 → R2) | F1 の右の扉 |
| RL | 0 | 96〜166 | F1 の写し(開かない) | F2 の左の扉。**見た目の座標 = v − 96**(R0 の写し) |
| R2 | 2.2 | 96〜110 | 反転の扉 | F2 の右の扉 |
| R3 | 2.2 | 110〜140 | 分岐 F3(左 1.1 施錠 / 右 3.3 は開いている) | 反転の扉 |
| R4 | 3.3 | 140〜166 | 出口(少し開いた扉と光の箱) | F3 の右の扉 |

- どのレーンも「4m の区画 × n ＋ 終わりの 2m(分岐の口は幅 3.8m に広がる)」。区画は 1 つのジオメトリ(床・天井・壁・幅木・灯具 2 種)を 14 個のメッシュで使い回す(`X105.pool`)。分岐の口・扉の壁・始まりの壁・入口の飾り(居室の扉 4 枚)・背後の壁・扉の板 11 枚は決まった部品で、近いレーン(今・次・前)の物だけ見せる。
- 材質は 1 つ(MeshStandardMaterial ＋ onBeforeCompile、`n2_x105_v2`)。面の種類は頂点の属性 `aSurf`(床・壁・天井・幅木・丸い灯具・角形の灯具・木・枠・金物・出口の光・扉の上の灯り)。どのレーンの光・見た目かは**メッシュの原点**で頂点ごとに決める(区画はレーンの中心線上、部品はレーンの端。扉の板の手前の面は手前のレーン)。
- 光: 区画の中心(天井 2.35m)の周期の灯り。フラグメントごとに近い 5 灯 ＋ 分岐の扉の上の灯り 2 灯 or 扉 1 枚の上 or 出口の光を計算(直接 ＋ 照り返し 0.16/(r²＋2))。灰色の区間の床だけ灯りの映り(Blinn-Phong 90 乗)。three.js のライトは足さない。
- ①伸びる: `stretch.from 10`・`keep 24`(F1 の初めの位置 = v 34)・`until 46`・`endMax 70`・`time 45`・`glide 3.0`(時間で終わった時、前を見ていない間に 70 まで 3 m/s)・`backGap 7.0`。伸びる途中の区画の切れ端(分岐の口より奥)はシェーダで捨てる。
- ②折り返し: RL に `closeAt 1.6`m 入ると F2 の左の扉が `closeSec 0.8` 秒で閉じ、`jumpAt 2.2`m 以上で閉じ切ったら z − 96 へ。その後 RL は消し(当たりも)、F2 の左右の施錠を入れ替え、105 の扉は「開かない」。
- ③反転: R3 に 0.2m 入ると `roll.sec 3.2` 秒の加減速でロール π。ロールが π/2 を越えたら、マウスの向き(`controls.pointerSpeed = −1`)と A/D を入れ替える(画面どおりに動く)。反転の扉は 2m 入ると閉じて施錠。死亡・空間から出るとロール 0。
- 追跡: `chase.at 121`・出現 (2.2, 110.7)・`slow 3.0` 秒は 2.5 m/s・`recover 0.35`・視点固定なし。歪みは `warpIn 2.0` 秒で 0 → 1。灯り: `offLead 4.0`・`offBehind 6.0`・`offRate 3.2` m/s。
- 死亡 → 105 の扉の前(扉を向く)。次に入ると**追跡の区間の前(R2 の始まり)**から(§8-4)。
- 霧: 濃さ 0.022・色 #050506(突き当たりの光が見える程度に薄く)。

## 5. シェーダ・テクスチャ・音

- テクスチャは 1 枚だけ: `x312.js` `makeCausticTexture()` が描く 256² の継ぎ目のない網の模様(整数倍の周波数の正弦の網、R8)。水の揺らぎの光は、これを 2 枚違う向きに流して重ねる(`caust()`)。他はすべてシェーダの中の手続き的な模様(カーペット・クロス・天井板・木目・タイル・モザイク)。参考フレーム(`ref/`)はテクスチャ化も複写もしていない。`assets/LICENSES.md` に自作として追記。

- 105 の歪み: 頂点シェーダ `0.24 × smoothstep(2.5, 17, 距離) × (sin(1.55t ＋ 0.42z)×0.7 ＋ sin(0.83t ＋ 0.16z ＋ 1.3y)×0.3)` を法線方向へ。

## 8. 判断した未決事項と申し送り

1. **「最初の地点」= R0 の入口(背後は 105 の扉)**。F2 の左の先(RL)は R0 の写しで、扉が閉まった後に z − 96 へ移す。扉ごしにカーペットの廊下が見えるのが「戻ってきた」の手がかり。
2. **折り返しは必ず 1 回起きるよう、F2 の施錠を通しで入れ替える**(1 回目: 右が施錠・左が折り返し / 2 回目: 左が施錠・右が先へ)。どちらの回も「片方は施錠」。2 回目は伸びず、R0・R1 をもう一度歩く(約 96m)。長すぎれば RL の移し先を R1 の始まりにする案がある。
3. **伸びるの終わり**は距離(v 46)か時間(45 秒)。時間で終わった時は、前を見ていない間だけ分岐を 70 まで動かす(見ている間に跳ばない)。
4. **105 で死んだ後のやり直しは、105 の扉の前から入り直すと追跡の区間の前(R2 の始まり)から**。「第4段の開始位置(105 の前)から再挑戦」を、戻る場所は 105 の前・中身は追跡の手前から、と解釈した(最初からだと約 250m 歩き直しになるため)。
5. **105 の扉は伸び始めたら戻る口でなくなる**(背後は壁)。折り返しの後に背後の扉は 105 の扉だが「開かない」。
6. **出口でメモを拾わずに出た時は、出る時に拾ったことにする**(第5段へ進む)。メモは出口の扉の手前の床。
7. **反転中は操作を画面に合わせる**(マウスの上下左右と A/D を入れ替える)。契約は「見た目だけ」。操作も逆にした方が怖いが、追いかけっこで理不尽になるのでやめた(要確認)。
8. **312 で溺れたら第3段の開始位置(管理室)**(指示どおり)。管理室からは 312 まで遠いので、312 の扉の前に戻す案もある(`x312.js` に `respawn(ctx)` を足せば変えられる)。
9. **312 の鍵を取った後にもう一度入ると、ふつうのプール**(北から出入りできる。反転・管理人なし。閉じ込めないため)。
10. **管理人は空間から出ると建物の EV ホールから巡回に戻す**(105 の出口・312 の戻り)。ロッカーのワープと同じ扱い。
11. **`enemy_ai.js` の `_reveal`(ロッカーの登場)の最初の姿勢を `fade 0` にした**。前の歩きの姿勢と 0.05 秒混ざり、最初の 1〜2 フレームに頭が閉じた扉の前へ出ていた(`?test=story` 15 番が前のケースの管理人の動きしだいで 7/8 になる真因)。見た目はロッカーの中に立っている姿勢から始まるだけ。
12. **プールの縁はどこからでも上がれる**(はしご・階段だけに限らない)。潜っている間だけ縁の外へ出ない。はしごは見た目。
13. **105 の建物の仕上げはシェーダの手続き的な模様**で、建物の GLB のテクスチャそのものではない(色・格子・カーペットの粒は寄せた)。入口の居室の扉 4 枚は番号のない札。
14. **水面の映り込み**は計算した点(天井の灯り)だけで、床や壁を映す再描画はしない(性能)。
15. 705・B1 の仮の小部屋は P5b-1 のまま(PointLight 1 灯 → 最初に入る時に全材質のシェーダを作り直す引っかかり)。P5b-2b ではシェーダの中の光にするとよい(§2)。
16. **検証環境の罠(内蔵ブラウザのモジュールのキャッシュ)**: ページの URL の `&v=` は import されるモジュールには効かず、内蔵ブラウザが古い `player.js` を使い続けた(312 のテストが泳げずに落ちる)。Cmd+Shift+R が効かない時は、ページ内で `fetch(各モジュール, { cache: 'reload' })` してから開き直すと新しくなる。
17. 調整値の候補(目視で決める): 105 の `stretch.keep 24`・`backGap 7`・`chase.at 121`・`offLead/offBehind`・歪みの 0.24m、灰色化の 10〜40m、312 の息 18 秒・`stretch.k 0.85`・管理人の `dist 1.2`・霧の濃さ。
18. 未実装(P5b-2b の範囲): 705 の柱の広間・B1 の白いトンネル、第7段の「窓の内側から見下ろす管理人」。
