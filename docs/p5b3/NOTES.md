# P5b-3 ユーザー実機指摘 3 回目(建物の修正 4 件)

DESIGN §2(段状セットバックの段落の末尾 ①〜④)と §7 の P5b-3 行の実装。EV の移動中の暗転を無くし、1F の食堂の扉をガラス扉に、シアターを鉄枠のガラス扉 2 枚の前室・北の壁のスクリーン・南の段床に作り直した(1F 再ビルド)。

## 1. EV の移動中の暗転(④)

### 原因
`main.js` の `elevator.onRideStart = (to) => world.focus(to)`。`world.focus(key)` は「key ±1 を読み、それ以外を解放」なので、**2 階以上離れた行き先**(1F→4F なら {3,4,5})では、乗った瞬間に**出発階(カゴを描いている階)の GLB が解放**されていた。プレイヤーの階キーは到着まで出発階のままで `world.setVisible([1])` を続けるため、移動中は描く物が何も無く、霧と背景の色だけになっていた(1F→4F で画面中央の平均輝度 225 → 13、四隅 39〜86 → 2〜8。到着した瞬間に戻る)。1 階ぶんの移動(4→5 など)は出発階が ±1 に残るので起きなかった。露出・GTAO・霧・カゴの天井の発光・`isReady` 待ちは原因ではなかった(移動中もカゴの灯りと天井の発光は出発階のカゴに付いていて、それごと消えていた)。

### 直し方
- `world.focus(key, { keep })`: keep の階は解放しない(`src/world.js`)。
- `elevator.onRideStart = (to) => world.focus(to, { keep: [playerLevel] })`(`src/main.js`)。移動中は「出発階＋行き先 ±1」を持ち(1F→4F で 1,3,4,5)、到着の `setPlayerLevel(4)` が `focus(4)` で出発階を解放する。到着の入れ替えはチャイムの前、扉が閉じたまま(`arrived` → 0.3 秒後に `opening`)なので、階の入れ替えは閉じた扉の裏で起きる。カゴの見た目は全階同じなので、入れ替えの前後で画面は変わらない。
- 移動中に 1 階ぶん多く GPU に載る(最大 4 階)。到着で直ちに 3 階に戻る。

### 検証
`?test=building` の `3d_ev_ride_no_blackout`: 1F のカゴの奥を向いて 4 を押し、扉が閉まり切った最初のフレームを基準に、`opening` が始まるまで毎フレーム画面中央と四隅(24×24px)の平均輝度を `gl.readPixels` で読む。**456 フレームで最大の差 1.4%**(閾値 15%。変更前は 94% 落ちる)。移動中の読み込み状況 `1` → `1,4` → (到着) `4`。

## 2. 食堂の扉 = 透明のガラス扉(①)
- データ: `DINING.door.glazed = 'sus'`(`data/build_building.mjs`)。開閉・当たり・共用扉の扱いは従来どおり。覗き穴は付けない。
- 作り(`tools/blender/build_floor.py glass_leaf`): 扉板 = ステンレスのヘアライン枠(縦框 6cm・吊元 5cm・上框 7cm・下框 16cm、`M_HairV`/`M_HairH`)＋両面のガラスの押縁＋見込み＋レバーハンドル(両面・吊元側へ伸びる)。三方枠と沓摺もヘアラインのステンレス。
- ガラス: 廊下端の窓と同じ `MX_CorrGlass` の 1 枚の面(実行時は `corrGlass()` = 両面の半透明 0.12・映り込み・汚れの粗さ。ライトマップなし)。**扉板の子のオブジェクト**(`DoorGlass_<id>`、n2_kind `corrglass`)にして扉と一緒に回す。ベイクの対象外・光を遮らない(既存の `CLEAR_KINDS`)。
  - 風除室の `M_GlassClear`(物理材質の透過)は使わなかった: 透過は画面に入るたびに不透明の物をもう 1 回描くため、1F の縦廊下の突き当たり(常に視界に入る)では重い。見た目は廊下端の窓と同じ系統で、中(卓・配膳カウンター)が廊下から見える。
- `tools/blender/build_exterior.py`: 外観の帯は階の GLB から `corrglass` を取り出すため、**扉板の子のガラスは除外**(館内の物。check_glb の「帯に建物の中の面」が 2 になった)。

## 3. シアターの入口 = 鉄枠のガラス扉 2 枚の前室(②)
- データ: 新しい部屋 `THEATER_V`(kind `vestibule`、矩形 x 7.8〜10.2・z 22.1〜23.5 = 幅 2.4m × 奥行 1.4m、室の北西の角)。外扉 = `THEATER_V.door`(廊下の壁 z 22.1、x 9.0)、内扉 = `THEATER.door`(前室の南の壁 z 23.5、x 9.0)。**2 枚の間隔 1.4m**。どちらも `common`・`glazed: 'steel'`。前室の南の壁に内扉の開口(`openings`)。
  - `THEATER` の矩形は従来どおり室全体(6.2×6.0m。前室を含む入れ子)。前室の東・南の壁が仕切る。管理人の「部屋」判定・家具の配置・隠れ場所の計算が室全体の矩形を前提にしているので、矩形を割らずに入れ子にした。`build_building.mjs` の「部屋重なり」の検算は `<id>_V`(kind vestibule)が親の矩形の中に収まる時だけ許す。
  - 空気: `theater_v`(前室、天井 2.4m)・`theater`(前室の南、z 23.5〜28.1)・`theater_n`(前室の東、スクリーンの前)。
- 作り(`glass_leaf` の `steel`): 暗いグレー〜黒のスチール(`M_SteelDark` base 0.05・粗さ 0.42・金属 0.3)の縦框 9cm・上框 10cm・下は 26cm の蹴板、大きなガラス面(`MX_CorrGlass`)、両面に縦長の押し手(ステンレスの角材 0.9m と上下の脚)。三方枠も同じスチール、沓摺はステンレス。
- 天井の高さが違う扉の垂れ壁: 内扉は前室 2.4m / 室内 2.8m。従来の垂れ壁は 1 枚の箱で、面の中心が低い側の天井より上になって前室側の面が張られなかった → **低い天井の高さで 2 段に分けた**(`build_door`)。
- 当たり: `walls.js` の共用扉の扉ブロッカがそのまま 2 枚とも付く(閉じていれば通れない)。
- ナビ(`src/ai_graph.js`): 廊下 →(`THEATER_V`)→ 前室の点 `1:TV`(9.0, 22.8)→(`THEATER`)→ 室内 `1:TH`。管理人は 2 枚とも押して開けて入る(`door_opened_generic:THEATER_V` → `:THEATER`、廊下から室内まで 5.1 秒)。
- 非常口サイン: 内扉の上(室内側)。前室の外扉の上には付けない(廊下側の扉の上は従来も無い)。
- story/rooms の扉 API: `doorApi.get/open/close/isOpen`・`openDoor`・E の「開ける」が 2 枚とも通る(テスト 11)。

## 4. スクリーンを北の壁へ、南を段床に(③)
- スクリーン(`build_1f_extras`): 北の壁(入口側)、**前室の東**の x 10.8〜13.4(幅 2.6m)・高さ 0.72〜2.27m。黒い額(`M_Sensor`)を壁から出してその手前に幕面。両脇の床にスピーカー(x 10.33〜10.73 / 13.47〜13.87、高さ 1.0、南を向く)。プロジェクターは最前段の上の天井(z 25.3〜25.7、y 2.62〜2.8、北を向く。最上段に立っても頭に当たらない)。
- 段床(`room.tiers`、`build_building.mjs C1F.tiers`): 西の壁際 x 7.8〜8.9 は平らな通路、x 8.9〜東の壁まで、北(スクリーン側)から **3 段**:
  | 段 | z | 高さ | 奥行 |
  |---|---|---|---|
  | 1 | 25.0〜26.0 | 0.3m | 1.0m |
  | 2 | 26.0〜27.0 | 0.6m | 1.0m |
  | 3 | 27.0〜28.1(壁の面 28.04) | 0.9m | 1.04m |
  暗いカーペット(`M_Carpet`、外殻のライトマップ)の上面・蹴上げ・西の側面、段鼻にアルミの見切り(`M_HairH`)、西の側面の段ごとに小さな足元灯(`M_StepLight`、ベイクで通路をわずかに照らす)。座る所 = 段ごとに座布団 5 枚(`cushion`、当たりなし)。ソファは最前列の 1 脚だけ残した(平らな床 z 23.95〜24.8、スクリーンを向く)。ローテーブルは撤去。落ちる物(空き缶)はソファの西の端の床へ。
- 天井: 室内(前室を除く)だけ **2.8m**(`air.ceil`。最上段 0.9 ＋目線 1.62 = 2.52m が天井 2.4m を超えるため)。`build_floor.make_zones` が `air.ceil` を空気の高さにし、天井の面と壁の面がその高さになる。`check_glb.mjs` の壁の面の高さの許容に `air.ceil` を加えた。
- 段を登る: プレイヤーには段差登りの仕組みが無かった(足元は常に階の床。階段は stairs.js の専用処理)→ **足元の嵩上げ** `world.floorAt(x, z)`(`src/player.js`)。段床の矩形の中では足元の高さを段の値へ 3.2m/s で寄せる(0.3m の段を約 0.1 秒)。段に当たりの箱は置かない(段の手前で止まらずにそのまま登る＝スロープの当たりと同じ効果)。`main.js` が階ごとの `room.tiers` から `floorAtFor(key)` を作って `player.setWorld` に渡す。
- 管理人: 経路・当たり・視線の判定は床のまま、見た目の足元の高さだけ段に乗せる(`main.js` の step で `enemy.root.position.y`)。最上段 0.9m は `AI.levelGap` 1.0 未満なので、段の上のプレイヤーも見える・届く。
- 隠れ場所 `L1_theater_back`: 旧位置(9.4, 27.4)は最上段の上になる → **段床の西の脇の平らな通路の奥**(8.38, 27.5、内扉の方を向く)へ移した。管理人が LURK でそこへ歩いて止まる(足元 0)ことを確認。
- `points`(管理人の部屋の点): entry (9.0, 24.1)・room (9.6, 24.5)・living (8.38, 26.6)。

## 8. 判断と申し送り
1. **ガラスは `MX_CorrGlass`(安い半透明)**: 指示の「風除室の自動ドアや廊下端の窓と同じ流儀」のうち廊下端の窓の方式。風除室の物理材質の透過は、縦廊下の突き当たり(食堂)・横廊下(シアター)で常に画面に入り、毎フレームもう 1 回描くので避けた。
2. **前室は THEATER の矩形の中の入れ子**(部屋を 2 つに割らない)。前室にいるプレイヤーも管理人からは「シアターの中」に見える。
3. **段床は当たり無し＋足元の嵩上げ**。プレイヤーに段差登りの仕組みが無かったため。管理人は経路・当たりは床のまま、見た目だけ段に乗る。段の上で襲撃ムービーが始まると、管理人の位置は床の高さで扱われる(最大 0.9m の差。気になれば attack_movie 側で足元の高さを足す)。
4. **天井 2.8m はシアターの室内だけ**(前室は 2.4m)。外観・2F には影響なし(2F の床は 2.9m)。
5. シアターの中は灯りが無く暗い(従来どおり。非常口サインと足元灯だけ)。スクショは懐中電灯つき。上映中の明かり・スクリーンの発光は物語で必要になったら。
6. 前室の外扉の上の非常口サインは付けていない(内扉の上だけ)。
7. EV: 移動中は最大 4 階ぶん GPU に載る(出発階＋行き先 ±1)。1F→7F でも同じ(1,6,7)。
