## 3. ベイクの有無と所要時間

- **1F: ベイクなし**(`--no-bake`)。現行コードで組んだ 1F は外殻・部屋の組とも、コミット済みの GLB とライトマップ UV が全ノード一致した
- **2〜7F: 再ベイクした**。理由は家具ではなく、**コミット済みの 2〜7F の GLB が現行コードより古かった**こと: P5b-3(シアター・食堂の扉)以降の build_floor で階段扉の上の壁(`Lintel_MST2〜7`・`Lintel_NST2`)の面が 8→12 頂点に分かれ、外殻のライトマップ UV の詰め直しで全体がずれる(1F 以外は P5b-3 の後に作り直されていなかった)。家具の材質だけなら不要だった
- 所要時間(Metal GPU・1024spp・2048px。外殻＋部屋の組): 2F 70+30s / 3F 68+34s / 4F 59+25s / 5F 50+25s / 6F 60+20s / 7F 37+838s(7F の部屋の組は別の GPU 負荷と重なって 14 分。普段は 20s 前後)。合計 約 25 分
- 見え方の変化なし: 2F・4F の廊下(EV ホール前から北)の平均輝度 66.0→65.9 / 94.8→94.8。部屋の組のライトマップは金属にした脚の所だけ暗くなる(金属は拡散 0 なのでライトマップを使わない)
- その後の材質の手直し(椅子の台座・tint)は再ベイクなしで書き出し(UV 一致を確認)

## 4. パイプライン(`tools/build.sh` に追加した引数。既定の動きは同じ)

- `--no-data`(building.json・テクスチャの再生成を飛ばす)/ `--no-exterior`(exterior.glb を作り直さない)/
  `--no-bake`(既存の webp と bake_info で書き出す。ライトマップ UV が変わらない時だけ)/
  `--safe`(GLB・manifest・ライトマップ webp を `build/.stage` に書いてから mv。別のサーバーが読み込み中でも壊れた GLB を返さない)
- 書き出しの成否はログの `exported` で見る(`-nt` は `--no-bake` だと同じ秒になり誤って止まった)
- 今回の手順: `tools/build.sh --no-data --no-exterior --safe --floor "2 3"`(以降 4 5・6 7)→ `--no-bake --floor 1`
- **UV が変わっていないかの比べ方**: 2 本の GLB の各ノードについて (位置, TEXCOORD_1) の組の集合が一致するか(材質の分け方が違っても同じ頂点なら同じ第 2UV)。
  スクリプトは scratchpad の `cmp_uv1.py`(GLB の JSON とバイナリを numpy で読む 40 行。必要なら tools/ に移す)。家具の材質だけ替えた時は 7 階とも差 0

## 8. 既知の妥協点

1. **机の天板に懐中電灯が映るのは、遊べる位置からはほぼ見えない(完了条件を満たせていない)**。原因は材質ではなく光の幾何: 懐中電灯は目の 16cm 下・12cm 右(player.js)にあり、
   水平な天板で懐中電灯が映る点(鏡面の点)はほぼプレイヤーの真下。当たりの半径 0.28m で目は天板の縁から 0.28m 以上離れるので、天板の縁でも鏡面の向きから 17.6° 以上ずれる。
   roughness 0.35(GGX の α 0.12)のハイライトは 10° で 1 割、17° で数% まで落ちる(クリアコート 0.18 はもっと細い)。実測でも机の近接の構図で鏡面反射の有無による画素差は 0(JPEG の雑音以下)。
   さらに world.js は金属以外の材質の環境反射を 0 にしているので、部屋の映り込みもない。
   試した代案: ニスの木部に共通の環境(metalEnv と同じ RoomEnvironment)を 0.04〜0.10 映す → 棚板が白く光り、暗い部屋で光源のない映り込みになるので不採用(scratchpad の試し画像のみ)。
   **見えるようにするには src 側の判断が要る**(例: x312.js の patchLamp と同じ要領で、ニスの材質だけ懐中電灯の向きから作った擬似の鏡面を足す/天板の粗さを契約より上げて広い鈍いつやにする=契約の数値から外れる)。メインの判断待ち
2. 312 の複製は §6 の src の 1 行が入るまで R4・R5 で布団が重なる。入っても R4・R5 の乱れた布団(src が色見本で作る)は織りなし
3. 織りは実物より粗い(6.3mm)。1.5m より遠いと mip で平らになり、遠目の布らしさは「しわの法線」と sheen だけ。sheen は照明(ライトマップ)の当たる布を約 1〜2 割明るくする(410 の全景の画面平均 27.35→28.0、+2%)
4. 金属は world.js が共通の環境を metalEnv 0.08(312 の複製は 0.25)で映すので、地の色(F0)を鋼の実物(0.5 前後)より暗く 0.10/0.22 にした(明るいと暗い部屋で脚が光って見える)。「黒い鋼管」の見え方
5. 2〜7F は外殻も再ベイクした(§3。見え方は廊下の輝度で同等を確認、細部の雑音の模様は変わる)
6. P6b-E1 との重なり: 410 の全景の平均輝度が +2%。E1 がチュートリアル場面 1(410)の輝度比の基準を私の差し替えの前に取っていると比が約 2% ずれる
7. 使わない色の布の材質の定義も manifest に載る(+0.03MB)

## 10. 形の作り込み(`tools/blender/build_rooms.py`)

- **角丸の箱 `B.rbox` / `IL.rbox`**: 面ごとの格子を「内側の箱へ寄せて r だけ押し出す」写像で丸める。丸めの帯は滑らかな陰影(頂点を共有＝軽い)、
  平らな中央の面は flat にする(Blender は flat の面との境を鋭い辺として扱うので、帯の陰影が平らな面ににじまない。支えの線が要らず三角形が少ない)。
  帯は 2 分割(0°→45°→90°)。滑らかな陰影なので 2 分割でも丸く見える。`warp`(局所座標の変位)と `n_in`(内側の分割)で曲げ・へこみ
- 机 `_desk`: 天板 25mm・縁の丸み 10mm(懐中電灯の照り返しの線が出る)・鋼板の側板の脚・前の幕板(天板の縁から 15mm 下がる)と引き出し
  (前板のまわりに 2mm 幅・0.5mm 奥の溝)・取っ手・奥の幕板
- ベッド `_bed`: フレームの角丸 10mm・頭の板＋張り出した笠木＋1.2cm 出た鏡板(段差)・角丸 25mm のマットレス(キルトの縫い目は法線
  `cloth_quilt_normal.jpg`、10cm 角)
- 掛け布団 `_duvet`: 格子(内側 7cm 間隔、縁は細かく)の高さ場。厚み 7cm、縁で半径 4.5cm の丸みで折れて 12cm 垂れ、裾は内側へ折り返す(厚みの見える縁)。
  上面にゆるい皺の尾根 3 本(整えた寝床)/5 本(乱れた寝床)＋弱い波。乱れた寝床は頭側に折り返しの山、部屋側(壁から遠い側)の足元の角がめくれて上へ返る。
  皺の位置は部屋の号室から決まる乱数(部屋ごとに違う・再生成しても同じ)
- 枕 `_pillow`: 角丸 3.5cm を細分し、縁を薄く・中央を 2.2cm くぼませる(乱れた寝床は少し傾く)
- 椅子 `_chair`: 座面(厚み 7cm・角丸 1.5cm・中央 1.2cm のくぼみ)・背もたれ(角丸・両端が 3.5cm 前へ反る)・ほぼ円柱の鋼の支柱。十字の台座は樹脂のまま
- 角丸にした物: 洗濯機・冷蔵庫・電子レンジ・洗面台(本体と天板)・エアコン・シューズケース(本体と天板)・壁の棚板。
  小さい部品(ベッドの脚・幕板の細い帯・防水パン・レンジ台の棚・椅子の台座)と小物(本・缶・服など)は丸めていない(三角形と容量のため)
- 金属の F0 をさらに下げた(脚 0.10→0.05、支柱 0.22→0.12): 角が丸くなると帯が共通の環境を映して暗い部屋で白い線に光ったため。クリアコートの粗さ 0.18→0.25
