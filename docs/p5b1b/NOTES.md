## 1. フリーズの真因と修正

**再現手順(実機と同じ)**: 221 で管理人が出る → 机の前から走って玄関 → 廊下を西へ → EV ホール(6.9, 21.2)→ 外階段の鉄扉 `MST2`(6.5, 21.2 で E)→ 踊り場 → 下りの段(レーン x 4.4〜6.0)を W で下りる。管理人は追跡中で踊り場まで来る。

**何が起きていたか**(仮説 a〜c をヘッドレスで再現して切り分け。例外・描画停止はなく、`frame()` は回り続けていた):
1. 段の上り下りの間、プレイヤーの「階」(`playerLevel`)は着くまで元の階(2F)のまま。外階段は折り返しなので、下りの終わりの方(1F の床まで 0〜1m)では XZ が 2F の踊り場の真下に来る。管理人の知覚・攻撃判定は XZ だけだったので、踊り場に来た管理人が「段の下の方のプレイヤー」を目の前に見つけて ATTACK した(高さの差 2.9m)。
2. 襲撃ムービー(`attack_movie.js`)が始まると `player.frozen` が立つが、段の移動(`stairs._advance`)は frozen を見ないのでプレイヤーは運ばれ続け、着いた瞬間に `frozen = false` に戻した。振り下ろしの時点ではプレイヤーは 1F にいるので**空振り**。
3. 空振りの後、管理人は CHASE に戻るが、**襲撃ムービーを終わらせる処理が無かった**(終わるのは死亡 → 復帰の時だけ)。ムービーは毎フレーム カメラの位置を管理人の顔の前に固定・FOV 44° にし続けるので、画面は管理人の顔を見上げたまま止まり、WASD もマウスも効かない = 体感の「フリーズ」。管理人はその後プレイヤーを見失って徘徊に戻るので、永久に解けない。
- 付随して見つけた同じ系統の不具合: (a) 段の途中で殺されると、復帰後も `stairs.active` が残り、段の上へ引き戻されて段の行き先の階へ移された。(c) 視点固定(`view_lock.js`)は始めた時の `frozen` を終わる時にそのまま戻すので、段の途中で始まって段が先に終わると `frozen = true` が残る(消灯の飛び出しが段の途中で起きると操作不能になり得た)。

**修正**:
- `enemy_ai.js` `_blocked(p)`: プレイヤーの足元の高さが管理人の階の床から `AI.levelGap` = **1.0m** 以上離れていれば遮られている扱い(見えない・近接の気づきなし・殴れない)。段の上の方(高さの差 1m 未満)ではこれまでどおり捕まる。
- `enemy_ai.js` `_attack`: 空振りで `onAttackMiss()` → `main.js` が襲撃ムービーを畳み(`movie.end({ restore: true })` = カメラの位置・向き・FOV を襲撃前へ)、他に止める理由が無ければ操作を返す。
- `main.js`: 襲撃ムービー・死亡演出の間は `stairs.update` を進めない(段の途中で殴られたら段の上で止まる)。復帰時に `stairs.cancel()`。
- `view_lock.js`: 終わった時の frozen = 「始めた時に止まっていた」かつ「まだ止める理由がある」(`holdFrozen` = `inputHeld()`: 段の途中・死亡演出・襲撃ムービー・視点固定・別空間の暗転・エンディング・隠れ場所・覗き穴)。
- 再現テスト `?test=story` **14 番** `14_chase_outer_stairs_no_freeze`(下の §6)。修正前のコード(`git archive` で別ポートに配信)で同じテストを走らせると失敗する(段の上で ATTACK・高さの差 2.9m、着いた後もムービーが残る・視点がプレイヤーの目に戻らない、段の途中の死亡で復帰位置がずれる、空振りでムービーと frozen が残る)ことを確かめてから直した。修正後は実機と同じ手順(221 の奥 → 飛び出し → 外階段で 1F)でも、着いた後に歩ける・「221号室へ戻れ」になる。

## 7. 判断した未決事項と申し送り

1. **冒頭の見せ場の引き金は「戸口を廊下側へ出た瞬間」**(扉が開いた瞬間ではない)。扉を開けて中に留まると見逃すため。カゴはその瞬間に 4F へ置き直す(最初は 1F。呼んでから来るまで待つと 7 秒以上かかり「数秒で乗る」にならない)。
2. **管理人はカゴが動き出した時点で姿を消す**。プレイヤーが階段で先回りして 2F の EV の前で待つと、空のカゴが開く(管理人は「2F にいる体」で眠っている)。降りてくる姿を見せるか・消えたままにするかは要確認。プレイヤーがカゴの戸口に立ち続ける・一緒に乗る、は 20 秒で姿を消して 2F で眠る(まれ)。
3. **ロッカーの寸法**: 奥行 0.40m・扉の最大 1.0 rad。標準的な 0.5m 奥行だとクローゼット(隠れ場所・そのまま残す)との隙間が無く扉が開けない。管理人の体の幅に対して内側 0.45m で肩がわずかに側板に入る(扉の陰・暗いので目立たない)。
4. **609(220 の鍵の部屋)にはロッカーを置かなかった**(指示どおり 221 と罠 3 室)。罠の部屋が「窓際にロッカーがある部屋」と見分けられる。609 にも開かないロッカーを置けば見分けが付かなくなる(要確認)。
5. **逃げる途中の死亡は飛び出しの前に戻す**(「管理人はもう 2F にいる体」の解釈)。逃げ切った後(鍵が机にある)の死亡は進行を保つ。復帰時の管理人は従来どおり 4F の EV ホール(`ENEMY_HOME`)から徘徊を始めるので、第1段の `'return'` で死ぬと 410 の近くに管理人がいる(P5a からの仕様。気になるなら第1段だけ 2F に置く)。
6. **逃げ切りの判定に「階を変えた」を含めた**ので、外階段で 1F に着いた時点で「221号室へ戻れ」になる(管理人は EV で追ってくることがある)。
7. **221 の引き金の深さは u 3.5m(洋室の入口)**。「奥へ進むと」を、浴室の壁を過ぎて洋室に入った所と解釈した。ロッカーの外の立ち位置 out まで約 1.7m。視点固定(2.57 秒)の間は動けないので、逃げ始めの余裕は「視点が戻ってから 0.6 秒」だけ。テストのボットは振り向きが一瞬なので 3.8m 以上離れるが、人がマウスで 180° 振り向くには短いかもしれない。調整は `AI.reveal.recover`・`burst221U`・ロッカーの `out`。
8. **消灯時の懐中電灯は敵の材質だけの光**(ロッカーの内側の面は照らさない)。本物の光を足すとシーンの光源数が変わって全材質のシェーダが作り直される(数十〜数百 ms の引っかかり)ため。必要なら P4 で内側に発光の小物を足す。
9. 視点固定(`view_lock.js`)の終わりの frozen の扱いを変えた(`holdFrozen`)。他の場面(EV の賭け・消灯の飛び出し)にも効く(段の途中で起きても操作が戻る)。
10. 第1段の EV の賭け: 管理人が眠っている間(状態 SCRIPTED)は起きない。冒頭の見せ場でカゴが 2F に着いた記録(`npcStop`)は残るが、221 で起きるのは 25 秒より後なので賭けにはならない。
11. 文言は「逃げろ」(第9段と同じ)・「221号室へ戻れ」。素材の追加はない(すべて実行時・Blender の生成。`assets/LICENSES.md` の追記なし)。
12. スクリーンショットの撮り方の注意: 止めて(`paused`)いる間に外観の読み込みが終わると、次の `step` まで外観の帯が表示のままになり室内が灰色に塗られる。`exterior.ready` を待つか、撮る前に 1 フレーム進める(実際のプレイでは次のフレームで直るので問題ない)。`pump(…, false)` は描かないので、レイキャストの前に `scene.updateMatrixWorld()` が要る(動いた扉板の行列)。
