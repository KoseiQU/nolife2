# P4a NOTES — 音のサンプル盤と常時ドローンの削除(2026-11-01)

## 1. ずっと鳴っていた「ジー」の正体と削除

### 特定の方法
- 通常プレイ(`index.html`)を内蔵ブラウザで開き、`AudioListener` の出力(`listener.gain`)に `AnalyserNode` を並列につないで 0.5 秒ごとに RMS を測った。
- 起動直後(管理人 SCRIPTED/PATROL、プレイヤーは 410)で RMS 0.0006→0.0026 と増え続け、`enemyAudio.hum.getVolume()` の上昇(0.03→0.15)と完全に連動した。`hum.stop()` だけで出力は **RMS 0・ピーク 0**(10 回連続)になった＝**常時鳴っていたのは `hum` 1 本だけ**。

### 正体
- `src/enemy_audio.js` の `hum`(`synthHum`。仮音名 `enemy_hum_loop_01`)。D2(73Hz)を基音にした低い男声の「んー」という鼻歌 11 秒のループを、管理人の頭のボーンに付けた `PositionalAudio` で**常時再生**していた。音量は状態ごとに PATROL 0.55・SCRIPTED 0.55・CHASE 0.9・DOOR 0.25。管理人がいる限り(どの階にいても距離減衰で小さく)鳴り続け、壁越しでは lowpass 600Hz で上の倍音が削れて、旋律より「ジー」という低いうなりに聞こえる。
- 他のループは常時ではないことを確認(残した):
  - EV のモーター(`elevator.js` `motor`):カゴが動く間だけ音量が上がる。一度乗ると以後はノードが音量 0 で再生され続ける(無音。§6 申し送り)
  - 風(`rooms.js` `wind`):バルコニー・屋上A にいる間だけ。屋内では gain 0
  - 105 の灯具のうなり・312 の水・705 の部屋鳴り・B1 の水(`src/spaces/*`):その空間に入っている間だけ。`leave` で止まる
  - 地下の滴り(`main.js updateDrips`):地下階段の区画と B1 だけ・間欠
  - 車のエンジン(`story.js _engine`):エンディングだけ

### 削除した内容(コミット cec7865)
- `src/enemy_audio.js`:`hum` の生成(`synthHum` 関数ごと)・再生(`resume`/`update` での `play`)・音量制御(`ENEMY_AUDIO.humVolume`・`humTarget`・`update` の追従)・`_makeSource` の頭ボーンへの取り付けと `isHum` を外した。`setState(state)` は AI から呼ばれるので残し、状態を記録するだけにした。冒頭のコメントに削除の経緯を書いた。
- `src/main.js`:見学モードだけ「ハミングを鳴らさない」ために分けていた `resumeAudio` を 1 本に(差が無くなったため)。
- テスト(`tools/test_*.js`)は `hum` を参照していなかったので変更なし。
- 削除後の確認:通常プレイで 6 秒間、listener の出力 RMS 0・ピーク 0(管理人の足音などの間欠音が鳴るまで無音)。

## 2. サンプル盤の使い方
- `python3 -m http.server 8001 --bind 127.0.0.1`(プロジェクト直下)→ **http://127.0.0.1:8001/samples/sound.html**
- 場面ごとに A/B/C の 3 候補。▶ で試聴(もう一度押すと止まる。再生しても選択はされない)、行を押すと選択。「3 つ続けて聴く」で A→B→C を順に鳴らす。`wav` でその候補を .wav で保存(P4b と同じ書き出し)。
- 選択はブラウザの `localStorage`(`nolife2.sound_choice.v1`)に自動保存され、再読み込みで戻る。上の章の丸ボタンは、その章を選び終えると金色になる。
- 下の「選択を書き出す」で `sound_choice.json` の中身(`{ "場面ID": "a", ... }`。選んだ場面だけ、並びはゲーム順)をテキストエリアに出し、クリップボードへコピーし、ファイルとして保存する。**保存したファイルを `samples/sound_choice.json` に置く**と P4b が読む(P4a ではファイル自体は作っていない＝まだ誰も選んでいない)。未選択の場面があれば数を表示する。
- 音量は候補どうしで揃えてある(下記)ので、音量差ではなく質感で選べる。

## 3. 場面数と候補の作り
- **69 場面 × 3 = 207 候補**、11 章(目覚め・410 と 4F／冒頭の見せ場・EV／管理人／1F・221・管理室／312 プール／105 長い廊下／6F の罠・220／正面玄関・駐車場・屋上／705 柱の広間／地下 B1／脱走・エンディング)。
  - 目安 25〜40 を超えたのは、指示の「最低限含めるもの」だけで約 55 あり、さらに各 NOTES の仮音(`room_fall_*`・`room_window_slide`/`room_climb`・`room_locker_*`・`door_latch_creak`・`x705_*`・`xb1_*` など)を漏れなく載せたため。仮音は 1 つ残らずどこかの場面に対応させた(`docs/p4a/sounds.md` 末尾の対応表)。近いものはまとめた:鉄扉(シアター・北階段・地下・B1 の踊り場)、扉がひとりでに開く(705 南・B1 戻り)、遠い悲鳴(105・B1)、異世界を抜ける/鍵を取った瞬間(B1 の release と key_drone)、窓と乗り越え。
  - BGM・音楽は作っていない。「静けさ」の候補(耳鳴り・ほぼ無音)を、管理人の窓越し・カゴの中・覗き穴・ゲームオーバーに入れた。
- **作り**:`samples/sound_lib.js`。道具箱 `Kit`(ノイズ 3 色・フィルタ・包絡・音程スイープ・固有振動の和＝金属/ガラス/ベル・粒＝紙/砂利/泡・スティックスリップの軋み・のこぎり波＋フォルマントの声・ループ用の床・種付きノイズの残響・反響)と、足音・ノック・鍵束・紙・ラッチ・心拍・泡・虫・エンジン・割れ物の形を組み合わせ、各候補は `render(ctx, dest, t0)` の 1 関数。生の `AudioContext` にも `OfflineAudioContext` にも組める。
  - 乱数は候補ごとに固定の種(場面 id＋候補 id のハッシュ)。何度描いても同じ波形 = 書き出しが再現する。
  - 3 候補は質感を変えた(例:足音「柔らかい/硬い/擦り」、環境「うなり/風/ほぼ無音＋家鳴り」、軋み「高い金属/低い唸り/途切れ途切れ」)。怖さの工夫は間(無音の後の一打)・不規則さ(引きずる歩調・体当たりの間隔)・低域(床が揺れる・気圧のうねり)。
  - **正規化**:`renderCandidate()` が 48kHz モノラルで描き、ピーク −6dBFS を上限に、RMS が上限(効果音 −18／環境 −26／静けさ −36 dBFS)を超えないよう下げる。実測で全 207 本のピークは −6.0dBFS 以下(静けさは −20 以下)。
- 一覧表 `docs/p4a/sounds.md`:場面 ID・説明・呼び出し元(ファイル:関数。「新設」は今は音が無い所)・今の仮音・書き出し名(案)・候補 3 つの説明、末尾に「仮音の名前 → 場面 ID」の対応表。`sound_lib.js` から生成(生成スクリプトは使い捨て。表を直す時は lib の `when`/`callers`/`temp` を直して作り直すのが正)。

## 4. 検証
- 内蔵ブラウザで `window.__SB.check()`(サンプル盤に入れた検証用の関数):
  - 全 207 候補を `OfflineAudioContext` で描画:例外・NaN・無音 0(全体 4 秒)。
  - 同じ `render` を起こした生の `AudioContext`(gain 0 の出口)にも組んで例外 0。
  - 正規化した音を `AudioBufferSourceNode` で鳴らし、**207/207 が `onended` で終了**。時間の都合で `playbackRate` 6 倍(5 回に分け各 30〜42 秒)。等倍の再生はボタン経由で別に確認(▶ で鳴り始め、長さの経過後に止まる表示に戻る)。
  - 選択 → 再読み込みで復元、書き出しの JSON・保存、を確認。
- 波形の包絡(0.25 秒刻み)を全候補で見て、設計どおりの所に音があるかを確かめた。これで**軋みの合成が bandpass でほぼ消えていた不具合**を見つけ、粒ごとの減衰振動に作り直した(28 か所が使う)。
- 耳での確認はしていない(エージェントは聴けない)。音色の良し悪しはユーザーの試聴が判定。
- スクショ 3 枚 `docs/p4a-screens/`:`p4a_01_board_top.jpg`(冒頭)・`p4a_02_board_enemy_selected.jpg`(管理人の章・選択済みの見た目)・`p4a_03_board_phone_export.jpg`(スマホ幅・書き出し後)。ヘッドレス Chrome(CDP)で撮影。

## 5. P4b への差し替え手順(案)
1. ユーザーが選んだ `samples/sound_choice.json` を読む。
2. 書き出しスクリプト(ブラウザで動く 1 ページ、例 `tools/export_audio.html`):`SCENES` から選ばれた候補を `renderCandidate()` → `encodeWav()` → `assets/audio/<フォルダ>/<場面ID>_01.wav`(`sounds.md` の書き出し名(案))。ブラウザからは直接ディスクに書けないので、まとめて zip で落とすか、小さな受け口(`python3` の 1 ファイルの PUT サーバ)で受ける。足音は種を変えて `_01〜_04`。環境音は頭と尻をクロスフェードしてループ点を作る。
3. 鳴らす側:`EnemyAudio`・`Elevator`・`Rooms`・`Story`・`spaces/*` の仮音の合成(各 `bufs`・`_sfx`・`burst`/`tone`)を、名前で引く共通のローダー(`src/audio_bank.js` のようなもの。`fetch` → `decodeAudioData`、読み込みまでは無音)に置き換える。`docs/p4a/sounds.md` 末尾の対応表がキーの対応。
4. 「新設」の場面(プレイヤーの足音・扉・懐中電灯・環境音・死亡・チェックポイントなど)は接続口を足す。環境音は場所(階・居室/廊下/屋外/空間)で 1 本だけ鳴らすバスにし、**常時ループにしない約束を保つ**(居室・廊下の環境音も「ほぼ無音」寄りが選ばれる可能性が高い)。
5. 管理人の気配(`enemy_presence`)は PATROL 中に 6〜15 秒おきの間欠で鳴らす(同じ階のときだけ。壁越しのこもりは既存の遮蔽の仕組み)。
6. 差し替えが 1 コマンドで済むよう、書き出しは「`sound_choice.json` を変える → 書き出しをやり直す」だけにする。声(台詞・TTS)は `docs/lines.md` の体系で別に扱う(P4a の範囲外)。

## 6. 判断と申し送り
- **鍵束の音**:§3.8 で「管理人の鍵束・鍵で開ける演出」は不採用だが、指示どおり「気配」の候補 A に入れた(音だけ。鍵で開ける動作は戻さない)。A が選ばれたら §3.8 との整合をメインで判断してほしい。
- **うなり系の候補**:ユーザーが嫌った「ジー」と同系統の、音程のあるうなりは 105 の灯具(`amb_x105` A。指示の「灯具のうなり」)と迷路(`amb_maze` A)だけに置き、他は広帯域・間欠・ほぼ無音にした。どちらも空間の中だけ。
- **EV のモーター**:一度乗ると以後ずっと音量 0 で再生され続ける(聞こえないが常時ノード)。`elevator.js` は今回触れない約束なので残した。P4b で止まったら `stop()` する。
- `door_locked` は、プレイヤーが開かない扉を引く音と管理人がノブを確かめる音(`enemy_audio` の `rattle`)を 1 つにまとめた(今も同じ `rattle` を共用している)。分けたくなったら P4b で種違いを作る。
- `room_fall` の候補は割れ物の質感 3 案。缶・本・ボトル・マグ・ファイルは選ばれた質感の作り方で P4b が派生させる。
- 6F の罠の偽の鍵(`decoy_key`)は今は `key_pickup_01` と同じ音。区別する場面として立てた。
- `locker_burst`(ロッカーから出てくる)は今は無音の所。P4b で `_reveal` の emerge に接続。
- `samples/sound_choice.json` はまだ無い(ユーザーが選んで保存する)。サンプル盤の `localStorage` は内蔵ブラウザで検証に使った分を消してある。
- 検証用の `window.__SB` はサンプル盤だけにある(ゲーム本体には入れていない)。
